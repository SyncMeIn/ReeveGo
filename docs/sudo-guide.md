# 临时 sudo 审批与托管免密 sudo 指南

Reeve-Go 坚持 **“绝不替 AI 命令自动注入 sudo 密码”** 的安全底线，同时通过两层机制优雅解决日常需要提权（如重启服务、部署文件）的运维场景。

---

## 1. 一次性临时 sudo 审批（无需开启常驻 sudo）

即使服务器或用户 ACL 未勾选「允许 AI 使用 sudo」，当 AI 发起 `sudo` / `sudoedit` / `doas` / `pkexec` / `su` 命令时：
- 系统会自动将其升级为 **`DANGEROUS` + `临时 ROOT/SUDO（仅本次有效）`** 审批单；
- **物理禁止限时免审批**：不能通过「批准 + 15m 免审」覆盖；
- **堡垒机审批人权限强校验**：仅限管理员（`admin`）或具备该资产组 `can_approve && allow_sudo` 权限的审批人可批准；
- 批准仅对本次单条命令生效，不修改主机或 ACL 持久化配置。

---

## 2. 托管免密 sudo（`/etc/sudoers.d/99-reevego-<user>-nopasswd`）

由于 AI 通道不代输 sudo 密码，非 `root` 登录账号若需执行 `sudo`，目标机须已配置免密 sudo。

### 密码登录主机（控制台一键托管）
1. 先对目标服务器执行 **「测试并锁定指纹」**（安全红线：未锁定指纹的主机拒绝发送 sudo 密码）。
2. 在服务器「编辑 / 策略」弹窗勾选 **「允许 AI 使用 sudo」**，界面自动探测目标机免密状态。
3. 选择模式：
   - **默认（不勾选最小化白名单）**：写入完整免密 `<user> ALL=(ALL) NOPASSWD:ALL`；
   - **勾选「使用最小化白名单」**：可指定目标身份（`run_as`，如 `www`）与允许命令（绝对路径列表或 `ALL`），并实时预览规则。
4. 点击 **「保存」**：后端自动复用已保存的 SSH 密码经 stdin 送入 `sudo -S`，通过 `mktemp` + `visudo -cf` 语法校验 + `install -m 440` 原子写入 `/etc/sudoers.d/99-reevego-<user>-nopasswd`；校验通过后才保存策略。
5. 随时可在同一面板点击 **「一键撤销托管免密」** 仅删除 Reeve-Go 托管文件，不触碰人工原有规则。

### 私钥登录主机（安全手动配置）
私钥登录主机没有保存的登录密码，Reeve-Go 不会索要或缓存 sudo 密码；弹窗会根据你的选项直接生成一条带 `visudo -cf` 校验的一键命令，点击 **「复制手动配置命令」** 在目标机终端执行后点 **「重新探测」** 即可。
